# AI 阅读评测契约

30 条固定输入，三个分组各 10 条。`clear_source` 的明确来源限于古籍原文及署名的公开平行文本，不代表其附录注疏已获核验。版本异文不自动判错，必须注明比较的版本。`multiple_views` 比较馆藏所录观点，不预先承认历史归属。`insufficient_evidence` 使用出处/年代存在疑点的《女诫》旧记录。

## 人工评价维度（每项 0–2 分）

| 维度 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 事实准确性 | 作者/作品/年代错配或无据史实 | 未见明显错配，但关键主张未核实 | 逐项主张能由原文或核实资料支持 |
| 引用真实性 | 引文杜撰、错来源或冒充核实 | 与馆藏匹配，原始版本未核实 | 引文及归属、版本定位均核实 |
| 解读完整性 | 无解读或回避主题 | 回应部分原文/观点 | 解释核心语义并交代证据局限 |
| 观点区分能力 | 混淆观点、用 AI 代言古人 | 分列观点但差异说明不足 | 区分每种观点的依据、差异及现代解释 |
| 不确定性表达 | 无据确定或生成假史实 | 通用提示 | 明确指出哪些归属/解释/异文尚不能确定 |

人工评语必须包含 case ID、输出版本、具体句子、依据/链接、评分理由。专家未审定的维度使用 null，禁止用模型自评分或成功 HTTP 状态代替。

## 自动指标

`evaluate.py` 只计算结构、引用 ID/逐字片段匹配、来源标签、是否保留多来源和不确定性、延迟、拒绝率、HTTP 状态。**引用匹配不是事实正确**。拒绝输出不能算事实正确；无输出时完整性应人工记 0。基线没有结构化引用的条目不评为引用真实，也不评为引用全错。

## 复现

```sh
# 在仓库根目录；实际调用已有 Worker/Workers AI，会产生该服务正常的模型用量
python3 evaluations/ai/run-live.py --output docs/ai-evidence/new-run.json
python3 evaluations/ai/evaluate.py docs/ai-evidence/new-run.json --output docs/ai-evidence/new-metrics.json
cd cf-worker
npm run typecheck
npm test
```

真实评测与契约测试分开保存。契约测试的受控模型/R2 返回只用于故障和边界验证，不能用来声称真实模型准确。脚本并发上限 3（默认 2），已有记录不会重放，重测使用新的输出文件以保留失败样本。每次实验应固定 Worker 版本，禁止在热更新期间比较延迟或成功率。
